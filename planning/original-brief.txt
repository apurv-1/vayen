I want you to build an MVP of a macOS app for talking to my local coding-agent sessions.

Context / problem:

I frequently have multiple coding agents running in parallel across Claude Code, Codex CLI, Cursor, etc.

A typical situation:

- I find 5–10 GitHub issues.
- I assign each issue to a different coding agent/worktree.
- The agents work independently.
- 30–60 minutes later, I come back.
- I barely remember what each issue was about.
- The agent transcripts are extremely verbose.
- To understand a completed or running agent, I currently export/copy its transcript into ChatGPT and ask questions like:
    - What was this agent trying to do?
    - What was the original problem?
    - What has it done so far?
    - What approach did it take?
    - Why did it choose that approach?
    - What files did it modify?
    - Is it actually solving the original issue?
    - Did it discover anything unexpected?
    - What should I review carefully?
    - What remains unfinished?

This workflow works extremely well for me, but manually copying transcripts around is stupid.

I want to remove that step.

## Product

Build a small macOS menu-bar application.

When I click the menu-bar icon, I should see my local coding-agent sessions.

Something roughly like:

┌─────────────────────────────────────────┐
│ My Agents                               │
│                                         │
│ ● Claude Code                           │
│   Fix tokenizer caching bug             │
│   ~/code/unsloth                        │
│   Working · 12m                         │
│                              [Talk]     │
│                                         │
│ ● Codex                                 │
│   Implement streaming benchmark         │
│   ~/code/llm-d                          │
│   Finished · 4m ago                     │
│                              [Talk]     │
│                                         │
│ ● Cursor                                │
│   Refactor auth middleware              │
│   ~/code/project-x                      │
│   Working · 7m                          │
│                              [Talk]     │
└─────────────────────────────────────────┘

The important feature is "Talk".

When I select an agent/session, the application should understand that agent's existing local transcript/session history.

I should then be able to have a VOICE conversation about that session.

For example:

Me:
"What the hell was this agent working on again?"

Assistant:
"You gave it GitHub issue #421. The bug was that X happened when Y. The agent traced it to Z and is currently modifying A and B."

Me:
"Why did it change parser.ts?"

Assistant:
"Because it found that..."

Me:
"Is its current approach actually consistent with what the issue asked for?"

Assistant:
"Mostly, but there's one thing I'd inspect..."

The important distinction:

I AM NOT trying to send voice commands to Claude Code/Codex/Cursor in V1.

I am talking ABOUT the coding session.

The coding agent continues doing its work independently.

Our app is effectively an intelligent, conversational observer of the session.

## Architecture constraint

This should be agent/harness agnostic.

Claude Code, Codex CLI, Cursor, etc. maintain local state/session/transcript information.

DO NOT assume their storage formats.

First investigate how the latest versions of these tools persist local sessions on macOS.

Look for things such as:

- JSONL
- JSON
- SQLite
- local databases
- conversation/session directories
- project metadata
- working directory
- timestamps
- tool calls
- assistant messages
- user prompts

Start with:

1. Claude Code
2. OpenAI Codex CLI
3. Cursor

Verify everything against current source code/documentation/local installations where possible.

Then design adapters:

ClaudeAdapter
CodexAdapter
CursorAdapter

which normalize sessions into something conceptually like:

AgentSession {
    id
    harness
    projectPath
    startedAt
    updatedAt
    status
    originalPrompt
    messages
    toolCalls
    metadata
}

Do NOT tightly couple the rest of the application to any particular harness.

Adding another coding agent later should ideally mean implementing another adapter.

## Session discovery

The application should automatically discover sessions.

I should NOT have to manually import transcripts.

Figure out:

- where sessions live
- how to enumerate them
- how to associate them with projects
- how to determine the most recently active sessions
- whether we can reasonably infer running / idle / finished state

Do not fake status.

If exact running state cannot reliably be determined from the persisted state alone, investigate process inspection, file activity timestamps, PID information, etc.

Document what is reliable and what is heuristic.

## Transcript updates

Running sessions should update without requiring me to reopen the application.

Prefer a lightweight mechanism such as filesystem watching when possible rather than aggressively polling everything.

The Q&A layer should be able to incorporate newly written transcript entries.

## Grounded conversation

This is extremely important.

The conversational model should answer from the actual session evidence.

It should NOT invent what the coding agent did.

Relevant context can include:

- original user prompts
- agent responses
- tool calls
- commands executed
- files inspected
- edits
- test output
- git diff
- commits
- current repository state

For MVP, don't overengineer RAG if the transcripts comfortably fit within model context.

Start with the simplest architecture that works.

## Voice

Use ElevenLabs for the conversational voice experience.

I already want ElevenLabs to be the voice layer, so integrate it cleanly behind a VoiceProvider abstraction if reasonable.

The interaction should feel extremely fast:

Click agent
→ Talk
→ "What is this thing doing?"
→ useful answer

Voice latency matters.

Text chat can exist for debugging/testing, but voice is the primary interaction.

## UX philosophy

This is NOT supposed to become a giant agent-management dashboard.

I specifically want something lightweight.

The menu-bar app answers:

"What agents do I have?"
"What are they doing?"
"Let me talk about one."

That's it.

Avoid adding:

- task creation
- agent orchestration
- Kanban boards
- complicated analytics
- cloud synchronization
- team collaboration
- agent-to-agent communication
- writing instructions back into active sessions

Those can come later if this proves useful.

## Local-first

The agent transcripts remain local.

Only the context necessary for the selected conversation should be sent to whichever model/voice API requires it.

Make this behavior explicit and easy to reason about.

Never modify the original coding-agent transcript/state files.

Treat those files as read-only.

## First milestone

I care about proving ONE workflow:

1. I start a Claude Code session in a repository.
2. Claude works on something.
3. Your menu-bar app automatically discovers it.
4. I see the session.
5. I click Talk.
6. I ask:
   "What are you working on?"
7. I receive a concise, accurate spoken explanation grounded in the actual Claude session.
8. I can cross-question it naturally.

If this works well, THEN add Codex and Cursor.

Do not prematurely build all three integrations.
